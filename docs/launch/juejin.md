## 标题

给 DeepSeek Harness 输入区装上 Markdown 实时渲染：一个社区插件的实现笔记

## 正文

用 [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness)（dsh）的 Web 界面写提示词时有一个小摩擦：输入区不渲染 Markdown。想加个粗体、列个清单、贴段代码，发送之前只能靠脑内预演排版。

我为此写了一个社区插件 [dsh-markdown-input](https://github.com/long6177/dsh-markdown-input)，把 Markdown 体验装进输入区和聊天记录。这篇文章把它的能力、实现路线和工程保障整理一遍——细节都有仓库文档背书，文末附链接。

### 它能做什么

**输入区实时渲染。** 插件经官方的 `conversation.composer` 选举链低优先级接管输入区，内嵌自带的 CodeMirror 6 编辑器，做成 Obsidian 式实时预览（本文唯一一次用这个类比）：粗体、斜体、行内代码、删除线以真实样式呈现，代码块带围栏折叠和语言浮标；光标所在行保留原文标记、光标移开后标记折叠（渲染模式），一键切换回纯源码（源码模式）。Enter 发送（中文输入法安全）、`Shift+Enter` 换行，打的字实时镜像进宿主草稿，页面刷新不丢。

<!-- 素材位 1：hero GIF（输入 → 渲染 → 发送 → 气泡） -->

**粘贴转换。** 从网页或 Word 复制富文本，直接粘贴进输入区，剪贴板里的 `text/html` 自动转成干净的 Markdown——语义保留、噪音去掉，模型收到的就是这段源码。`Ctrl/Cmd+Shift+V` 仍然直插纯文本，纯文本、文件、图片的粘贴行为不变。

<!-- 素材位 2：粘贴转换前后对照（静态图） -->

**用户消息 Markdown 化。** 已发送的用户消息和排队插话的 steering 消息在聊天气泡里按 Markdown 渲染（复用宿主自带的渲染管线），@提及、/技能、会话引用的内联 chip 全部保留；作者敲下的换行也按硬换行保真呈现。

<!-- 素材位 3：用户消息渲染效果（静态图） -->

**逐面降级。** 插件的每个部件启用前先探测宿主能力：内置接管面板（审批、提问、子代理）需要输入区时照常按优先级抢占；某个宿主面缺失时只失去对应功能、文本面不受影响；渲染出现异常时卡片级 error boundary 自动退回原生输入区，草稿不丢。

### 为什么是「接管」

这条路线不是第一直觉，而是两轮真机验证后的选择，中间还绕过一次弯路：

- 周边的附加槽位只能贡献小部件，改不了文本面本身——实时渲染的核心命题落在它们够不到的地方；
- 「只画不改」的绘制层路线试过：浏览器绘制 API（CSS Custom Highlight）只提供颜色/描边级别的属性，没有字重和字形，「真加粗」在这条路上是浏览器硬上限，alpha 阶段按真机结论退役；
- 接管是官方已有先例的模式（审批、提问、子代理面板都走同一条选举链），配合 `overlay` 语义，被接管的内置输入区保活隐藏、草稿状态不丢，内置面板也照常抢占。

接管带来一张明确的重建清单：被隐藏的原生控件（工具行、目标栏、上下文量表、统计、工作区行等）要在卡片里逐件重建。为什么必须重建、每条事实的上游源码出处、以及我们写给上游的愿望清单，都整理在这篇工程记录里：仓库内 `docs/design/why-takeover.md`（扩展点全景见同目录 `docs/design/extension-points.md`）。

### 工程保障：让 alpha 敢用

上游 dsh 处于 developer preview、官方明说会有破坏性变更，一个接管型插件怎么把这个风险管住？本仓库的做法：

1. **逐面能力探测 + 独立降级**：每个部件先探测自己的宿主依赖（服务、RPC、投影键），缺谁降谁，不牵连文本面；
2. **error boundary**：渲染异常时整卡卸载、静默回落原生输入区，草稿经宿主草稿 API 保全；
3. **真机重测仪式**：每次发布附带 ≤8 条验收清单、逐条真机对照，累计 21 个版本的清单索引公开在仓库里（`docs/release/README.md`，同时是实测矩阵的依据）；
4. **漂移监视**：一个每天跑的仓库工作流探测上游版本、Release、白名单路径与官方契约文档四路信号，出新版就开票、一版一票跑全套测试——把「上游又变了」从被动发现改成例行公事。

### 安装

```sh
dsh plugin --profile web add dsh-markdown-input   # npm
```

### 状态与风险披露

- 插件当前为 **alpha**、积极开发中；
- 上游是 developer preview、存在破坏性变更，本插件跟随 `0.2.0-rc.x` 版本线：`0.2.0-rc.2` 已真机逐项重测（实测矩阵见仓库 README），更新的上游版本由漂移监视流程逐版跟踪验证，未验证的版本会在矩阵里显式标注。
